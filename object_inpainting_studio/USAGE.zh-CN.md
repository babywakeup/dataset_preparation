# 数据生成 Web 使用手册

适用：Object Inpainting Dataset Studio，本项目的独立节点编辑器。

新增节点：[Mask 内自动颜色分区](COLOR_REGIONS.zh-CN.md)，输入原图和 Mask 自动分色，无需指定颜色数量；该说明包含区域选择、按 `[0,1]` 提取独立 32×32 代表色色块、保存方式和函数类型接口表。

生成换色训练输入：[FLUX.2 衣服随机换色](RANDOM_RECOLOR.zh-CN.md)，从真实 target 和 GrayMaskNode 输出的 RGB 涂灰原图生成随机颜色的 source，不接受黑白 Mask 直接连接，包含随机种子复现和反向训练的配色说明。

> **最重要的区别：节点上的“仅保存当前张 · 不循环”只处理一张；处理整个文件夹必须点击画布顶部“运行全部 · 写入磁盘”。**

## 条件重试：生成到达标才保存

画布顶部 **↻ 条件循环** 支持 1～32 个独立或串联的循环。主入口是 **＋ 添加循环**，不必先启用，也不用先选择种子；不是任意回流连线，不支持重叠、嵌套或上一轮图片反馈。

1. 先连接生成、评分和保存节点，然后点 **＋ 添加循环**（面板折叠时也可点击）。
2. 依提示点击画布中具体节点的**标题**，按 **start 起点 → end 终点 → condition 条件** 的顺序完成向导。同类节点添加多次也只绑定点到的那个实例。
3. 起点通常选生成节点；终点选普通计算节点，例如评分节点，而**不是** SaveImages。条件节点恰有一个数字 / 布尔输出时，点标题即可选中；有多个输出时再点具体输出圆点。图片 / 文本不能作为条件。
4. 在循环卡片设置比较符和阈值；默认数字条件 `<= 10` 只是示例，布尔条件默认 `== true`。数字支持 `<`、`<=`、`>`、`>=`、`==`、`!=`，布尔仅 `==` / `!=`。`ColorSimilarity.score` 越小越接近。
5. 再点 **＋ 添加循环**，按同样方式配置第二个、第三个循环。每张卡片可独立命名、删除或重选起点 / 终点 / 条件，颜色与编号对应画布角色标记；点卡片中的节点名称可定位。
6. 最终保存目标是所有循环共用的独立选择：只有一个 SaveImages 时自动选中；多个时点 **画布选择最终保存目标**，再点具体保存节点标题。最终保存可直接连接已验收循环内部的图片，不必为每张待保存图片额外加终点。
7. 点击 **检查单图计划 · 不推理 / 不写盘**，核对每个循环范围和实际顺序，再点 **条件运行当前张 · 通过后保存**。改配置后须重新检查。
8. 文件夹模式继续用 **↻ 逐张**、保存目标、重新检查、试跑 / 运行全部。每张图片从头执行自己的全部循环，重置次数、种子及固定缓存。条件试跑只处理过滤后当前 `index` 的一张。

例如：起点点 `fluxrandomrecolor_2`，终点点 `colorsimilarity`，条件再点 `colorsimilarity`，设置 `score <= 10`。循环体自动包含换色 → 自动分色 → 色块 → 色差四个节点。无需反向连线；`seed=-1` 保持每次随机，也无需先改成 0。

### 循环卡片与高级选项

- 终点与条件可以是同一个节点，也可以分别指定。范围为起点后继与“终点 / 条件祖先”的交集，不会无边界扩展到最终保存。多个循环按 DAG 的实际依赖排序，不按卡片添加顺序硬跑。
- 默认只需点节点；**高级 · 多起终点 / 种子 / 重试限制** 中可增删多个起终点和递增种子，设置最大尝试次数（1～1000，含首次）、超时（0 禁用，最多 86400 秒）、耗尽失败 / 跳过。普通下游节点若消费循环中间输出，必须将来源声明为附加终点；最终保存不受此额外声明限制。
- 起点的非负 INT 字面量 seed 自动加入递增名单，每轮加 1；`-1` 保持随机，不加入递增名单，不会自动改用户 seed。高级设置中仍可明确调整名单；固定种子且未递增的确定性节点可能每轮相同。
- 每个循环可添加多个条件，在本循环内选择 all / any；**不同循环之间始终全部通过**才继续最终保存。后一个循环重试不会重跑前面已经通过的循环。失败 / 超时不会自动保存最好的一轮。
- 点选不会拖动标题、创建连线或修改输入绑定。Esc 结束当前点选，保留已经选好的项；未完成配置会明确报错，不会自动替换失效节点。改选、改名、删除使计划失效，但保留会话和历史预览；删掉最后一个循环恢复普通保存。
- 下载 / 导入保留循环 ID、名称、具体节点 ID 与输出名，移动节点不改变绑定。点选状态不保存。运行 / 检查 / 状态未知期间禁止配置；轮询不重建聚焦输入。
- 旧版启用开关、兼容入口和配置面板已删除，页面只保留多循环卡片。旧 flat `conditional_loop` 导入时自动转换为 `conditional_loop={loops:[...]}`，保留起点、种子、条件、比较值、重试上限和保存目标，仅补原来缺省的设置；原文件不修改。失效引用 / 非法值保留并提示修正，不会自动替换节点或取消验收；原始配置损坏时需明确点击“删除无效配置”再添加。
- 右侧任务记录显示当前循环及其尝试次数；历史评分按循环 ID / 名称区分，可下载完整 JSON 报告。

### 验收、缓存与停止规则

- 每个循环先生成再评估，通过后执行所有显式终点并保留结果，继续下一个循环；全部通过后才最终保存。all / any 只能使用**本循环同一轮**的评分，绝不拼接失败轮结果。
- 保存直接使用各循环达标轮缓存，不额外生成，所选保存节点仅执行一次。画布可有多个保存目标，但本次只执行选中的那个；被裁剪执行图中的其他写盘节点、非法中间输出逃逸和直接工作流输出会被拒绝。
- 固定祖先跨尝试复用，前序已验收结果跨后续循环复用，均深拷贝隔离。依赖尚未通过循环的桥接节点不能提前冻结为固定缓存；不同文件不复用图片结果，模型加载缓存独立保留。
- 普通非保存节点的 **测试此节点** 仍是单次调试，不进行条件验收。启用条件时，普通保存入口会被拦截并提示使用条件运行，避免误存未通过结果。原有最近成功预览仍保留，但不代表后台条件任务的当前输出。
- 推理异常立即结束当前图片，不会当作“评分不达标”反复重试；文件夹是否继续下一张由原有“单个文件出错后继续处理”控制。耗尽策略选“跳过”则计入跳过数，不计成功，也不写盘。
- 超时及取消在节点边界协作检查，包括长节点返回后、保存前；不强制打断 GPU 推理。已进入写盘的达标轮会完成并报告已保存路径。任务只保存在服务进程内，刷新可恢复进度，服务重启不可恢复。
- 条件配置由 Studio 后台解释；普通 CLI / DAG 拒绝带条件元数据的图，不能静默忽略验收。暂不支持重叠 / 嵌套循环、状态反馈、历史最优、持久队列或去噪步骤级取消。
- `ColorSimilarityNode.score` 是纯色色块间的原始 ΔE00，越小越接近；如用它做阈值判断，输入必须是你要比较的代表色色块，不能把整张生成图直接当作整图颜色质量评分。

## 端口统一命名与连线提示

节点卡片和右侧说明还显示 **入口类 → 出口类**，例如 `GrayMaskInputs → GrayMaskOutputs`。代码中的每个 `execute()` 参数和返回值均已标注类型；完整类定义与 28 个节点对照见 [节点类型指南](../docs/NODE_TYPES.md)。

画布端口、参数输入、右侧说明和输出预览统一显示 **格式名 · 中文用途**。同格式使用同名，原图 / 生成结果通过中文用途区分；涂灰图、参考图、伪彩色等容易误接的内容单独命名。

| 显示名称 | 实际含义 | 典型对应关系 / 原内部字段 |
| --- | --- | --- |
| `rgb_image` | 普通 RGB 图；用途注明原图、裁剪图或生成图 | 读取原图 `target`、文件夹 `image`、裁剪 `cropped` → 分割 / 分色 `image`、涂灰 `target` |
| `mask` | 黑白或灰度 Mask；用途注明物体 / 编辑 / 所选区域 | 分割 `object_mask` → 涂灰 `edit_mask`；两者用途不同，需主动确认 |
| `masked_rgb_image` | 编辑区域涂为 RGB(128,128,128) 的完整 RGB 图，**不是黑白 Mask** | 涂灰节点 `source` → 随机换色输入 `mask` / 组合样本 `source`；换色输出 `masked_source` 也是这种格式 |
| `rgba_image` | 带透明通道的图 | 透明抠图 `rgba` → 白底参考节点 `rgba` |
| `reference_rgb_image` | RGB 参考图 | 提取参考图 `reference` / 白底节点 `rgb` → 组合样本 `reference`；生成节点多槽显示 `reference_rgb_image_1`～`3` |
| `imgN`（色块输出） | 每个端口各一张 RGB 32×32 纯色图 | 色块节点的 `indices` 决定数量与顺序，分别连接评分输入 / 保存项；见 [色块动态输出](COLOR_REGIONS.zh-CN.md) |
| `image_list` | 图片列表兼容接口 | 保存节点 `images`；旧色块列表连线仍兼容，新色块节点不用列表 |
| `color_regions` | 运行时颜色区域集合，不是 JSON | 自动分色 `regions` → 选择区域 / 提取色块 `regions` |
| `label_map` | 整数区域编号图，**不是二值 Mask** | 自动分色 `labels`，不可接 `mask` 输入 |
| `overlay_rgb_image` / `palette_rgb_image` | 伪彩色叠加图 / 区域平均颜色填充图 | 自动分色的 `overlay` / `palette`，不要误当真实原图或二值 Mask |
| `color_rgb_image` | 随机候选纯色色块 | 随机换色 `sampled_color`，不是实际生成图的颜色测量 |
| `imgN` / 自定义保存名称 | 任意模式的动态保存项 | 默认 `img1`～`img4`，可按需增删；名称决定子目录，内部 ID 和连线保持稳定 |
| `input_dir` / `output_dir` | 输入文件夹 / 保存目录 | 文件夹 / 保存节点内部字段都仍为 `dir` |

- 点击输出圆点：**亮绿色**表示用途匹配，**蓝色**表示类型兼容但用途需核对，**暗色**表示类型不兼容或自身节点。中文用途与悬停提示可进一步区分原图、参考图、编辑 Mask 等。
- 推荐只是连线提示，不会自动改线，也不保证尺寸、坐标、图像内容正确；同类型但用途不同的合法连接仍可手动建立。回路仍会被原有检查拒绝。
- **旧工作流无需修改。** 这是显示名统一，内部字段、API、JSON 连线和磁盘文件名保持兼容。悬停端口或查看右侧输入说明可见“内部字段”。本文其他章节及接口示例中的旧字段仍可据此对应。
- 最容易混淆的一条链：**制作灰色遮挡输入的 `masked_rgb_image` 输出 → 随机换色的 `masked_rgb_image` 输入**，不再需要靠两个不同的 `source` / `mask` 名字猜测。

## 1. 下次使用时，先看这张清单

1. 在服务器启动 Studio，通过浏览器打开页面。
2. 点击 **Load workflow**，导入已保存的工作流。
3. 在文件夹节点 `folder` 的 `dir` 填服务器输入目录。
4. 在保存节点 `save` 的 `dir` 填服务器输出目录。
5. 文件夹节点切换为 **↻ 逐张**，全部处理时设 `index=0`。
6. 点击顶部 **重新检查**，核对图片数量、当前文件、输出目录和保存终点。
7. 先点击 **试跑当前张 · 写入磁盘**，检查生成质量。
8. 确认后点击顶部 **运行全部 · 写入磁盘**。
9. 查看右侧 **↻ 逐张任务 · 执行记录**，确认成功和失败数量，下载 JSON 报告。
10. 点击 **Download workflow** 保存本次配置。

**试跑不会自动跳过已经处理的图片。** 试跑第一张后再从 `index=0` 运行全部，会再次生成第一张，并保存为新的文件。

### 节点运行失败时怎么看原因

- 单节点测试 / 当前张试跑失败：状态栏显示真正失败的节点 ID、节点类型、异常类型和原因；画布标红失败节点，右侧预览显示同一错误。
- 点击下游节点可能触发上游执行。错误会保留最初失败的上游节点，不会误标成所点击的保存 / 选择节点；修正输入后重试会清除旧错误。
- 文件夹逐张任务：右侧每张图片的失败记录包含节点及原因；下载 JSON 报告可查看完整结果。失败项的 `node_error` 含 `node_id`、`class_type`、`error_type` 和 `message`。
- 服务终端输出错误原因和完整异常链，不再只有 HTTP 422。若要反馈问题，复制错误文本和相关堆栈即可，不必只截访问日志。
- API 保留字符串 `detail`，节点运行错误额外返回结构化 `node_error`。工作流校验 / 批处理规划错误未必对应已执行节点，此时阅读 `detail`；终端同样会记录原因。
- 正常停止批处理不会被记为节点失败。原生库崩溃、进程被系统杀死等无法被 Python 捕获的情况，不保证能生成节点错误记录。

### 删除节点

- 点击节点标题右上角 **×**，或选中节点后点击右侧 **删除此节点**；也可选中节点后按 **Delete**。
- 在输入框、文本编辑区或按钮上操作时，Delete 不会触发画布节点删除；不会接管 Backspace。
- 删除会断开该节点的所有连线，移除直接引用它的工作流输出；下游节点保留，断开的输入恢复节点默认值，没有默认值则置空。状态栏列出需要重新连接的输入。
- 相关预览、错误、布局和逐张计划会清理；删除循环输入会关闭逐张模式，需要重新选择文件夹及保存终点。
- 单节点 / 当前张试跑中、批量任务运行 / 停止中、任务状态待确认时禁止删除。
- 删除只修改当前画布，**不会删除服务器图片、模型或已经保存的文件**；没有撤销功能，需要保留的流程请先下载工作流。删除后重新下载可保存本次修改。
- 删除模型节点不会主动清空服务进程中的模型缓存，因此不保证释放 GPU 显存。

## 2. 启动与访问

在服务器上、Diffusers 仓库根目录执行：

```bash
bash examples/dataset_preparation/run_object_inpainting_studio.sh
```

默认地址是 <http://127.0.0.1:7860>。保持服务终端运行；在该终端按 `Ctrl+C` 会停止服务。

### VS Code 远程连接服务器时

1. 在远程 VS Code 的 **端口 / Ports** 面板转发服务器端口 `7860`。
2. 用本地浏览器打开转发后的地址；实际本地端口以 VS Code 显示为准。
3. 浏览器虽然在本地，读图、模型推理和保存图片仍发生在服务器上。

可通过 `--port` 修改监听端口。只有确实需要从其他机器直接访问时才修改 `--host`：

```bash
bash examples/dataset_preparation/run_object_inpainting_studio.sh --host 0.0.0.0 --port 7860
```

服务可访问服务器文件、执行模型并写入文件，没有登录保护。不要直接开放到公网；优先使用 SSH / VS Code 端口转发，并只分享给可信用户。

启动脚本默认使用仓库内的虚拟环境。若提示 Python 不可执行，可通过 `OBJECT_INPAINTING_STUDIO_PYTHON` 指定已有的、安装了所需依赖的 Python 解释器。

## 3. 路径填写在哪里：全部是服务器目录

| 配置位置 | 含义 | 注意 |
| --- | --- | --- |
| 文件夹节点 `folder` → `dir` | 待读取图片的服务器文件夹 | 目录需要存在 |
| 保存节点 `save` → `dir` | 保存生成结果的服务器根目录 | 保存时会创建目录，需要写权限 |
| 右侧底部 **Output dataset directory** | 完整 JSONL 数据集导出的目录 | **不是文件夹逐张保存的输出设置** |

当前测试输入可填写：

```text
/data/ttt/diffusers/examples/dataset_preparation/test_imgs
```

输出建议另选目录，例如下面的路径只是示例，请按需要修改：

```text
/data/ttt/diffusers/examples/dataset_preparation/generated_images
```

- 建议始终填写服务器上的绝对路径，避免相对路径随服务启动位置变化。
- `folder.dir` 和 `save.dir` 都必须填写，不能只填其中一个。
- 逐张运行时，文件夹的 `dir`、`recursive`、`index` 和保存节点的 `dir` 应直接填写，不要用其他节点连接这些参数。
- 保存目录不能是输入目录本身或输入目录的上级。若保存到输入目录的子目录，批量扫描会排除该输出子目录；仍建议输入、输出分开。
- 页面 **选择图片…** 会把本地图片上传到服务器临时目录，适合单张调试。它不是整个本地文件夹的同步功能；批量处理前请先把图片上传到服务器固定目录。
- 临时上传图片在服务停止后会被清理。下载工作流只保存路径，不会把图片或模型打包进去。

**编辑输入框后按 Enter，或点击其他位置使其失去焦点，才会提交修改。** 然后点击 **重新检查**。

| 节点“参数与单节点测试” | 展开参数、填写目录或提示词、测试当前节点 |
| 画布顶部逐张工具栏 | 选择保存终点、整理 / 定位流程、检查数量、试跑或运行全部 |
| 右侧节点说明与输出 | 查看节点用途、端口说明、测试方法和预览；点击预览图片可放大 |
| 右侧逐张任务区 | 查看进度、当前文件 / 节点、错误、停止任务和下载报告 |
| 右侧底部 Sample preview / Export | 运行完整样本预览或 JSONL 数据集导出，不等同于自定义逐张图片保存 |

注意：**空白画布、完整示例、单节点练习、逐张处理示例都会替换当前画布**。切换前先下载工作流，避免丢失修改。

### 画布的颜色

- **绿色**：随每张输入重复执行的路径。虚线范围框标明循环范围。
- **琥珀色**：固定输入分支，不遍历它；目前仍会在每一轮读取 / 执行该分支，并非跨图片缓存。
- **灰色**：不在本次保存终点的上游，不执行。
- 节点还有文字角色标记，不必只凭颜色判断。

**整理流程** 自动按依赖排列节点；**定位流程** 回到文件夹输入。点击顶部节点列表可定位相应节点，实际分支关系以画布连线为准。

## 5. 当前服装生成工作流

两个工作流文件：

- [原单张工作流](../object-inpainting-workflow%20%281%29.json)：固定读取一张上传图片，没有文件夹循环入口和保存终点。
- [循环版工作流](../object-inpainting-workflow-loop.json)：已增加 `folder` 和 `save`，并开启逐张模式；输入、输出目录初始留空，导入后需要填写。

循环版的大致流程如下，实际节点分支以画布为准：

```text
文件夹 ↻ → 读取当前原图 → SAM3 按 cloth 分割 → Mask 转 RGBA → 白底参考图 → FLUX 生成
                  │                │                                  ↑
                  ├────────────────┼──────────────────── 原图参考 ─────┘
                  └─────────────── 灰色遮挡图

保存终点汇合：原图 + 灰色遮挡图 + SAM3 Mask + FLUX 生成图
```

- `folder.path` 连接原来的 `loadtarget.path`，每轮换一张输入，后面的已有连接不需要修改。
- `sam3textmask.text` 是要分割的物体描述，当前为 `cloth`，不是 FLUX 的生成提示词。
- FLUX 的 `reference_1` 来自原图，`reference_2` 来自白底参考图，`reference_3` 为空。
- 修改商品图要求时，编辑 `fluxkleinreference.prompt`。
- 生成尺寸、步数、引导强度和随机种子在 FLUX 节点内配置，不是右侧用于数据集划分的全局 `seed`。
- 同一张图片分到多个处理分支，仍然属于同一轮，不会分别消耗下一张输入。

### SAM3 Mask 太小时的设置

**SAM3 内的膨胀逻辑和两个膨胀参数已删除。** 从左侧添加 **Mask 膨胀（独立） / MaskDilationNode**，或使用第 ⑬ 项单节点练习；连接 `SAM3.object_mask → MaskDilation.mask`。该节点也支持 SAM2、颜色分区和读取节点的 Mask，纯 CPU 运行，无需重复分割。

| 所在节点 | 参数 | 默认值 | 含义 |
| --- | --- | --- | --- |
| `MaskDilationNode` | `dilation_steps` | `1` | 膨胀次数，非负整数；0 关闭 |
| `MaskDilationNode` | `dilation_kernel` | `3` | 方形核边长，当前 Mask 像素；必须为正奇数，1 不扩展 |
| `SAM3TextMaskNode` | `threshold` | `0.5` | 物体置信度阈值，范围 0～1；降低可保留较低置信度匹配，不是直接扩大 Mask |
| `SAM3TextMaskNode` | `mask_threshold` | `0.5` | 像素 Mask 阈值，范围 0～1；适当降低可能保留较不确定的边缘，也可能增加背景 |

**建议在独立节点中先用 `dilation_steps=2`、`dilation_kernel=11`，SAM3 两项阈值保持 0.5。** 在没有碰到边界时，方形膨胀向四边的最大扩展距离为 $r = s(k-1)/2$（$s$ 为次数，$k$ 为核边长），该设置为 10 像素。距离相对于当前 Mask，不按原始文件或生成图尺寸换算。

- **编辑分支**：`MaskDilation.mask → GrayMask.edit_mask`；**参考抠图分支**可继续 `SAM3.object_mask → MaskToRGBA.mask`。这样只分割一次，参考图不额外包含膨胀背景。若确实需要扩大抠图范围，再把该分支改接膨胀输出。
- 独立节点输入是 `mask`，输出是 `mask` / `bbox` / `quality`，入口 / 出口类为 `MaskDilationInputs` / `MaskDilationOutputs`。输出尺寸不变、模式为 L；二值输入保持二值，灰度输入保留灰度，不改动原 Mask。
- 膨胀节点的 `bbox` 来自**最终非零区域**，右 / 下边界不包含且不越过图片边界；SAM3 的 `bbox` 则仍是原始分割范围。裁剪扩展区域时请接膨胀节点的 `bbox`。
- 膨胀节点 `quality` 显示次数、核及前后非零面积，不是模型分数。空 Mask 保持空，框为 `[0, 0, 0, 0]`，不能直接用来做非空裁剪；SAM3 的空分割仍会报错。
- **旧工作流兼容**：导入带 SAM3 旧膨胀参数的文件时自动删除旧字段、插入独立节点，保留旧数值并重接原 Mask / bbox 消费者与图输出。旧 SAM3 默认次数 0 保持为 0，不会误用新节点默认 1。CLI 与后端也执行相同迁移；图中可看到新增节点，导入后可整理布局。没有旧字段的图保持原连接。
- 原完整数据集流程的 `ExpandMaskNode` 仍使用共享 config，保留供既有完整示例 / CLI 使用；自定义图片工作流使用新的独立节点，不需要修改全局配置。
- 膨胀可能覆盖邻近物体 / 背景。编辑后提交数值，再测试膨胀节点、检查 Mask / bbox 预览后生成；重启服务并刷新页面可看到新入口。

### 文件夹参数

| 参数 | 设置 | 含义 |
| --- | --- | --- |
| `dir` | 服务器输入目录 | 支持 PNG、JPEG、WebP、BMP、TIFF |
| `recursive` | `0` | 只读当前文件夹 |
| `recursive` | `1` | 包含子文件夹 |
| `index` | `0` | 从排序后的第一张开始 |
| `index` | `1` | 从排序后的第二张开始 |

图片按相对路径名排序，不是上传顺序或修改时间。任务开始时固定文件列表，运行中不要更改输入文件。

只有两张输入时，`index=0` 会处理两张，`index=1` 只处理最后一张。运行全部的实际含义是：**从 index 指定的图片处理到末尾**。

## 6. 四种运行按钮，不要混淆

| 按钮 | 处理范围 | 保存到磁盘？ | 请求接口 |
| --- | --- | --- | --- |
| 普通节点 **测试此节点 · 自动预览** | 当前输入对应的该节点及必要上游 | 否 | `POST /api/node/preview` |
| 保存节点 **仅保存当前张 · 不循环** | 当前输入对应的保存节点及必要上游 | 是，只保存一组 | `POST /api/node/save-images` |
| 顶部 **试跑当前张 · 写入磁盘** | 按批量目录过滤规则选择 index 对应的一张 | 是，只保存一组 | `POST /api/batch/preview` |
| 顶部 **运行全部 · 写入磁盘** | 从 index 到末尾，每张执行所选保存终点的必要上游 | 是，逐张保存 | `POST /api/batch` |

**↻ 逐张** 只切换模式，**↻ 查看逐张流程** 只选择 / 展示循环范围，都不会自行启动批量任务。

**重新检查** 使用 `POST /api/batch/plan` 检查目录、数量和结构，不运行分割或生成模型，也不写出图片。检查数量成功不代表每张图片都可解码或模型一定可用。

第一次分割或生成可能先加载权重。看到终端进度条 `8/8`，表示当前一张图片的 8 个推理步骤完成，**不是处理了 8 张图片**。总图片进度看右侧任务区的“已处理 X / N”。

普通测试和单次保存会复用同一页面已完成且仍有效的上游结果。例如先测试 N 再测试 N+1，N 不会重复推理；状态栏分别列出“实际执行”和“复用上游”。直接再次测试 N 仍会重跑 N（可用于重新生成随机结果），依赖旧 N 的下游预览标记为历史结果，但不自动移除图片。

普通编辑不清空整个执行会话：例如只修改保存目录、组文件名、保存项名称 / 数量或新增下游连线，不会使未变化的上游 FLUX 重新推理。服务端按节点输入、上游输出版本、相关配置以及输入文件 / 文件夹图片的大小和修改时间决定是否复用；真正修改生成提示词、种子或参考图时仍会重算受影响的分支。新建 / 导入工作流或刷新页面会重置会话；重启服务、空闲超过 15 分钟或缓存被容量限制淘汰后，必要上游会重新执行。空闲从推理结束后计算，长时间模型加载 / 推理不消耗空闲 TTL。缓存仅在服务进程内保留真实输出对象，不随工作流导出；每进程最多 8 个会话、每会话 64 个节点。

**预览显示与执行缓存独立**：每个节点在当前画布保留最近一次成功输出。编辑参数、测试下游、重试中或重试失败都不自动删除旧图；可能过期的图片显示“历史预览”，不代表当前输入已验证通过。点击节点卡片或右侧输出的“隐藏预览”才隐藏，“显示预览”可恢复，隐藏状态在后续运行和界面重绘中保留；折叠参数、切换逐张模式不折叠预览。再次成功测试会更新该节点的最近输出；删除节点、新建 / 导入流程或刷新页面会重置相应预览，本功能不提供跨页面存档或多版本图片历史。

保存操作本身每次执行，固定文件名冲突仍报错，不会因为缓存而跳过写盘。顶部“试跑当前张”和“运行全部”保持独立执行，不复用手动预览会话，避免把上一张图片的结果带入循环。

## 7. 结果保存在哪里，如何对应原图

当前循环版的保存关系为：

| 保存端口 / 子目录 | 图片内容 |
| --- | --- |
| `img1` | 原图 |
| `img2` | 灰色遮挡图 |
| `img3` | SAM3 的物体 Mask |
| `img4` | FLUX 生成图 |

同一次处理的图片共享文件名，均保存为 PNG；整组文件名留空时，每次处理使用不同的随机编号。白底参考图仍参与生成，可按需添加保存项单独保存。

- **动态数量**：保存节点默认显示四个图片项；点击 **＋添加图片** 可增加到 8 项、12 项或更多，没有固定数量上限。点击该项旁的 **×** 删除输入及其连线，不删除磁盘文件。已有项不会重新编号，删除的编号也不会在当前工作流中复用；预览、批量运行或状态检查期间不能增删或改名。
- **逐项命名**：图片输入口旁直接填写 `target`、`source`、`mask`、`reference` 等保存名称，按 Enter 或移开焦点生效；名称只决定子目录，改名不会断开连线。留空时使用该项原始 ID，例如 `img8`。右侧绑定面板也可编辑名称；它不是额外的字符串连线口。
- **整组文件名**：参数 `filename` 留空，沿用同组共享的随机 UUID。可直接填写 `sample_001` / `sample_001.jpg`，或连接文件夹节点的 `filename`；去掉最后一个扩展名后统一保存为 PNG。例如保存名称为 `target`、整组文件名为 `sample_001.jpg` 时，路径为 `输出根目录/target/sample_001.png`。
- **安全与冲突**：名称不能是路径、`.` / `..` 或包含控制字符；保存项名称不能重复（忽略大小写）。保存子目录不能是符号链接。写盘前检查全部本轮目标；目标文件已存在时明确报错，既不覆盖，也不自动换名。空输入跳过，不会把 `img3` 重新编号为 `img1`；非法图片不会产生本轮文件。磁盘写入失败会回滚本轮已创建文件，可能留下空目录。
- **图片列表兼容**：保留可选 `images` 输入，直接连接 **提取区域颜色 · 32×32** 的 `images`，每项分别保存到 `images_0`、`images_1` 等自动命名子目录，顺序与索引列表一致；可与动态图片项同时保存，共享整组文件名。列表子目录暂不支持逐项改名，不要将其他保存项命名成这些目录。详见 [颜色色块保存说明](COLOR_REGIONS.zh-CN.md#colorregionswatchesnode独立-3232-颜色图)。
- **旧图兼容**：导入旧 `img1`～`img4` 工作流时自动补充保存项信息，旧目录名、空端口跳过和随机文件名行为不变。工作流下载 / 导入会保留自定义名称、已删除项和下一项编号；报告 `paths` 仍以稳定的 `imgN` / `images_N` 为键，实际路径显示自定义目录。
- 保存保留各路图片自身尺寸和模式，不会自动将原图、Mask 和生成图统一尺寸。
- 整组文件名留空时重跑新增文件；使用原文件名或固定组名时，重跑遇到已有结果会报错。输入中同主干的不同扩展名图片也会冲突。不会自动跳过已经处理的图片。
- **下载 JSON 报告** 可查看源图片路径与本轮输出路径的对应关系，不包含图片本身。
- 文件夹逐张保存只写出图片和任务报告信息，不自动生成训练 JSONL；JSONL 导出是另一条完整数据集流程。

## 8. 进度、失败、停止和恢复

- 右侧显示当前文件、当前节点、已处理数量、成功数量和失败数量。
- 默认勾选 **单个文件出错后继续处理**；坏图或某轮失败会记入报告，再处理下一张。
- 不勾选时，遇到第一个文件错误就停止。完成后要检查失败数量，不要只看“已完成”。
- 页面只展示最近 20 条文件结果；完整列表使用 **下载 JSON 报告**。
- **停止任务** 是协作式停止，需要等待当前节点返回，不能立即打断正在执行的模型推理。已成功保存的图片保留。
- 当前只允许一个批量任务运行。任务提交时固定流程快照，之后修改画布不会改变这个正在执行的任务。
- 刷新页面可恢复同一服务进程中的最近任务记录，**不代表恢复画布编辑**；画布请通过下载 / 导入工作流恢复。
- 重启服务会丢失内存里的任务记录，不会删除已写出的结果。服务重启不会自动断点续跑。
- 如果提示“响应丢失，任务可能已启动”，先点击任务区 **刷新 / 重试** 确认，不要反复提交。
- 手动从某张继续时，先根据报告确认排序和成功 / 失败情况，再设置 `index`。修改输入列表后，旧的索引不一定仍指向同一图片。

## 9. 保存与恢复自己的流程

**Download workflow** 保存节点、连线、画布位置、全局配置和循环模式。**Load workflow** 从本地选择 JSON 文件导入，后端会校验节点和连线。

工作流不是项目压缩包，不包含原图、权重、生成结果和任务报告。恢复前请确保服务器输入路径、模型路径仍然有效。

建议在以下操作之后下载一次：完成连线、修改提示词 / 模型参数、设置目录、开始长时间批量运行之前。

## 10. 常见问题速查

| 现象 / 提示 | 优先检查 |
| --- | --- |
| “批量运行前请在保存节点直接填写 dir 输出目录” | 展开画布中的 `save` → 填 `dir` → Enter；不是右侧底部的 Output dataset directory |
| 文件夹有两张，但只跑一张 | 日志是否为 `/api/node/save-images` 或 `/api/batch/preview`？改点顶部“运行全部”；同时检查 `index` 是否为 1 |
| 看见 `8/8`，不知道跑了几张 | 这是单张推理步数，看右侧“已处理 X / N”才是总图片进度 |
| “运行全部”是灰色 | 是否开启 ↻ 逐张、连接保存终点、填写两个 dir、完成重新检查；是否已有任务、预览或未确认的提交在进行 |
| 改目录后页面仍用旧值 | 在输入框按 Enter 或离开输入框，再点“重新检查” |
| 找不到保存节点 | 点击“整理流程”，或通过顶部节点列表定位；保存终点通常在流程右侧 |
| 出现多个保存分支 | 从顶部“保存终点”下拉框选择本次运行的节点；只执行它的必要上游 |
| 保存终点依赖多个文件夹 | 当前不支持自动配对两个文件夹；一次循环的上游只保留一个文件夹输入 |
| “文件夹不存在”或没有图片 | 填服务器目录，不是本地电脑目录；检查路径、格式和 recursive |
| 日志里 `memory_attention_rope_theta` 弃用警告 | 该警告本身不表示循环失败；看后续是否有异常及任务结果 |
| 模型找不到或首次加载很慢 | SAM3 / FLUX 使用已安装的本地模型；查看节点“说明与测试”和服务器异常，不要重复点击运行 |
| 旧上传图突然无法读取 | 临时上传目录可能在服务停止时已清理；重新上传或改用服务器固定目录 |
| 页面仍显示旧按钮文案 | 强制刷新浏览器；后端代码更新后还需重启服务 |

### 每次正式批量运行前，最后核对

- [ ] 输入目录在服务器上，文件列表正确。
- [ ] 保存目录与输入分开，具有写权限。
- [ ] `index=0`，或确实希望从中间开始。
- [ ] 选择了正确的保存终点，顶部数量符合预期。
- [ ] 提示词、分割对象和生成参数已确认。
- [ ] 已试跑并检查图片，知道试跑也会写入磁盘。
- [ ] 已下载工作流；批量结束后下载报告。
- [ ] 点击的是画布顶部 **运行全部 · 写入磁盘**。
