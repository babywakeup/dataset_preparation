# 数据生成 Web 使用手册

适用：Object Inpainting Dataset Studio，本项目的独立节点编辑器。

新增节点：[Mask 内自动颜色分区](COLOR_REGIONS.zh-CN.md)，输入原图和 Mask 自动分色，无需指定颜色数量；该说明包含区域选择、保存方式和函数类型接口表。

生成换色训练输入：[FLUX.2 衣服随机换色](RANDOM_RECOLOR.zh-CN.md)，从真实 target 和 GrayMaskNode 输出的 RGB 涂灰原图生成随机颜色的 source，不接受黑白 Mask 直接连接，包含随机种子复现和反向训练的配色说明。

> **最重要的区别：节点上的“仅保存当前张 · 不循环”只处理一张；处理整个文件夹必须点击画布顶部“运行全部 · 写入磁盘”。**

## 1. 下次使用时，先看这张清单

1. 在服务器启动 Studio，通过浏览器打开页面。
2. 点击 **Load workflow**，导入已保存的工作流。
3. 在文件夹节点 `folder` 的 `dir` 填服务器输入目录。
4. 在保存节点 `save` 的 `dir` 填服务器输出目录。
5. 文件夹节点切换为 **↻ 逐张**，全部处理时设 `index=0`。
6. 点击顶部 **重新检查**，核对图片数量、当前文件、输出目录和保存终点。
7. 先点击 **试跑当前张 · 写入磁盘**，检查生成质量。
8. 确认后点击顶部 **运行全部 · 写入磁盘**。
9. 查看右侧 **↻ 逐张任务 · 执行记录**，确认成功和失败数量，下载 JSON 报告。
10. 点击 **Download workflow** 保存本次配置。

**试跑不会自动跳过已经处理的图片。** 试跑第一张后再从 `index=0` 运行全部，会再次生成第一张，并保存为新的文件。

## 2. 启动与访问

在服务器上、Diffusers 仓库根目录执行：

```bash
bash examples/dataset_preparation/run_object_inpainting_studio.sh
```

默认地址是 <http://127.0.0.1:7860>。保持服务终端运行；在该终端按 `Ctrl+C` 会停止服务。

### VS Code 远程连接服务器时

1. 在远程 VS Code 的 **端口 / Ports** 面板转发服务器端口 `7860`。
2. 用本地浏览器打开转发后的地址；实际本地端口以 VS Code 显示为准。
3. 浏览器虽然在本地，读图、模型推理和保存图片仍发生在服务器上。

可通过 `--port` 修改监听端口。只有确实需要从其他机器直接访问时才修改 `--host`：

```bash
bash examples/dataset_preparation/run_object_inpainting_studio.sh --host 0.0.0.0 --port 7860
```

服务可访问服务器文件、执行模型并写入文件，没有登录保护。不要直接开放到公网；优先使用 SSH / VS Code 端口转发，并只分享给可信用户。

启动脚本默认使用仓库内的虚拟环境。若提示 Python 不可执行，可通过 `OBJECT_INPAINTING_STUDIO_PYTHON` 指定已有的、安装了所需依赖的 Python 解释器。

## 3. 路径填写在哪里：全部是服务器目录

| 配置位置 | 含义 | 注意 |
| --- | --- | --- |
| 文件夹节点 `folder` → `dir` | 待读取图片的服务器文件夹 | 目录需要存在 |
| 保存节点 `save` → `dir` | 保存生成结果的服务器根目录 | 保存时会创建目录，需要写权限 |
| 右侧底部 **Output dataset directory** | 完整 JSONL 数据集导出的目录 | **不是文件夹逐张保存的输出设置** |

当前测试输入可填写：

```text
/data/ttt/diffusers/examples/dataset_preparation/test_imgs
```

输出建议另选目录，例如下面的路径只是示例，请按需要修改：

```text
/data/ttt/diffusers/examples/dataset_preparation/generated_images
```

- 建议始终填写服务器上的绝对路径，避免相对路径随服务启动位置变化。
- `folder.dir` 和 `save.dir` 都必须填写，不能只填其中一个。
- 逐张运行时，文件夹的 `dir`、`recursive`、`index` 和保存节点的 `dir` 应直接填写，不要用其他节点连接这些参数。
- 保存目录不能是输入目录本身或输入目录的上级。若保存到输入目录的子目录，批量扫描会排除该输出子目录；仍建议输入、输出分开。
- 页面 **选择图片…** 会把本地图片上传到服务器临时目录，适合单张调试。它不是整个本地文件夹的同步功能；批量处理前请先把图片上传到服务器固定目录。
- 临时上传图片在服务停止后会被清理。下载工作流只保存路径，不会把图片或模型打包进去。

**编辑输入框后按 Enter，或点击其他位置使其失去焦点，才会提交修改。** 然后点击 **重新检查**。

## 4. 页面各区域怎么用

| 区域 | 用途 |
| --- | --- |
| 顶部工具栏 | 空白画布、完整示例、Validate、下载 / 加载工作流 |
| 左侧练习区 | 打开单节点练习，或进入“↻ 逐张处理示例” |
| 左侧添加节点区 | 向当前画布添加节点，不替换整个流程 |
| 中间画布 | 拖动节点标题移动；点击输出圆点，再点击兼容的输入圆点完成连线 |
| 节点“参数与单节点测试” | 展开参数、填写目录或提示词、测试当前节点 |
| 画布顶部逐张工具栏 | 选择保存终点、整理 / 定位流程、检查数量、试跑或运行全部 |
| 右侧节点说明与输出 | 查看节点用途、端口说明、测试方法和预览；点击预览图片可放大 |
| 右侧逐张任务区 | 查看进度、当前文件 / 节点、错误、停止任务和下载报告 |
| 右侧底部 Sample preview / Export | 运行完整样本预览或 JSONL 数据集导出，不等同于自定义逐张图片保存 |

注意：**空白画布、完整示例、单节点练习、逐张处理示例都会替换当前画布**。切换前先下载工作流，避免丢失修改。

### 画布的颜色

- **绿色**：随每张输入重复执行的路径。虚线范围框标明循环范围。
- **琥珀色**：固定输入分支，不遍历它；目前仍会在每一轮读取 / 执行该分支，并非跨图片缓存。
- **灰色**：不在本次保存终点的上游，不执行。
- 节点还有文字角色标记，不必只凭颜色判断。

**整理流程** 自动按依赖排列节点；**定位流程** 回到文件夹输入。点击顶部节点列表可定位相应节点，实际分支关系以画布连线为准。

## 5. 当前服装生成工作流

两个工作流文件：

- [原单张工作流](../object-inpainting-workflow%20%281%29.json)：固定读取一张上传图片，没有文件夹循环入口和保存终点。
- [循环版工作流](../object-inpainting-workflow-loop.json)：已增加 `folder` 和 `save`，并开启逐张模式；输入、输出目录初始留空，导入后需要填写。

循环版的大致流程如下，实际节点分支以画布为准：

```text
文件夹 ↻ → 读取当前原图 → SAM3 按 cloth 分割 → Mask 转 RGBA → 白底参考图 → FLUX 生成
                  │                │                                  ↑
                  ├────────────────┼──────────────────── 原图参考 ─────┘
                  └─────────────── 灰色遮挡图

保存终点汇合：原图 + 灰色遮挡图 + SAM3 Mask + FLUX 生成图
```

- `folder.path` 连接原来的 `loadtarget.path`，每轮换一张输入，后面的已有连接不需要修改。
- `sam3textmask.text` 是要分割的物体描述，当前为 `cloth`，不是 FLUX 的生成提示词。
- FLUX 的 `reference_1` 来自原图，`reference_2` 来自白底参考图，`reference_3` 为空。
- 修改商品图要求时，编辑 `fluxkleinreference.prompt`。
- 生成尺寸、步数、引导强度和随机种子在 FLUX 节点内配置，不是右侧用于数据集划分的全局 `seed`。
- 同一张图片分到多个处理分支，仍然属于同一轮，不会分别消耗下一张输入。

### 文件夹参数

| 参数 | 设置 | 含义 |
| --- | --- | --- |
| `dir` | 服务器输入目录 | 支持 PNG、JPEG、WebP、BMP、TIFF |
| `recursive` | `0` | 只读当前文件夹 |
| `recursive` | `1` | 包含子文件夹 |
| `index` | `0` | 从排序后的第一张开始 |
| `index` | `1` | 从排序后的第二张开始 |

图片按相对路径名排序，不是上传顺序或修改时间。任务开始时固定文件列表，运行中不要更改输入文件。

只有两张输入时，`index=0` 会处理两张，`index=1` 只处理最后一张。运行全部的实际含义是：**从 index 指定的图片处理到末尾**。

## 6. 四种运行按钮，不要混淆

| 按钮 | 处理范围 | 保存到磁盘？ | 请求接口 |
| --- | --- | --- | --- |
| 普通节点 **测试此节点 · 自动预览** | 当前输入对应的该节点及必要上游 | 否 | `POST /api/node/preview` |
| 保存节点 **仅保存当前张 · 不循环** | 当前输入对应的保存节点及必要上游 | 是，只保存一组 | `POST /api/node/save-images` |
| 顶部 **试跑当前张 · 写入磁盘** | 按批量目录过滤规则选择 index 对应的一张 | 是，只保存一组 | `POST /api/batch/preview` |
| 顶部 **运行全部 · 写入磁盘** | 从 index 到末尾，每张执行所选保存终点的必要上游 | 是，逐张保存 | `POST /api/batch` |

**↻ 逐张** 只切换模式，**↻ 查看逐张流程** 只选择 / 展示循环范围，都不会自行启动批量任务。

**重新检查** 使用 `POST /api/batch/plan` 检查目录、数量和结构，不运行分割或生成模型，也不写出图片。检查数量成功不代表每张图片都可解码或模型一定可用。

第一次分割或生成可能先加载权重。看到终端进度条 `8/8`，表示当前一张图片的 8 个推理步骤完成，**不是处理了 8 张图片**。总图片进度看右侧任务区的“已处理 X / N”。

普通测试和单次保存可能重新运行必要上游；不要为了“刷新预览”反复点击高成本生成节点。

## 7. 结果保存在哪里，如何对应原图

当前循环版的保存关系为：

| 保存端口 / 子目录 | 图片内容 |
| --- | --- |
| `img1` | 原图 |
| `img2` | 灰色遮挡图 |
| `img3` | SAM3 的物体 Mask |
| `img4` | FLUX 生成图 |

同一次处理的四路图片使用相同的随机文件名，均保存为 PNG；不同次处理使用不同文件名。白底参考图仍参与生成，但在这个工作流中不单独保存。

- 这些目录的含义取决于你连接到 `img1`～`img4` 的内容，不是保存节点固定的语义。
- 空端口跳过，不会把 `img3` 重新编号为 `img1`。
- 保存保留各路图片自身尺寸和模式，不会自动将原图、Mask 和生成图统一尺寸。
- 重跑会新增文件，不会自动按原始文件名覆盖，也不会自动跳过已经处理的图片。
- **下载 JSON 报告** 可查看源图片路径与本轮输出路径的对应关系，不包含图片本身。
- 文件夹逐张保存只写出图片和任务报告信息，不自动生成训练 JSONL；JSONL 导出是另一条完整数据集流程。

## 8. 进度、失败、停止和恢复

- 右侧显示当前文件、当前节点、已处理数量、成功数量和失败数量。
- 默认勾选 **单个文件出错后继续处理**；坏图或某轮失败会记入报告，再处理下一张。
- 不勾选时，遇到第一个文件错误就停止。完成后要检查失败数量，不要只看“已完成”。
- 页面只展示最近 20 条文件结果；完整列表使用 **下载 JSON 报告**。
- **停止任务** 是协作式停止，需要等待当前节点返回，不能立即打断正在执行的模型推理。已成功保存的图片保留。
- 当前只允许一个批量任务运行。任务提交时固定流程快照，之后修改画布不会改变这个正在执行的任务。
- 刷新页面可恢复同一服务进程中的最近任务记录，**不代表恢复画布编辑**；画布请通过下载 / 导入工作流恢复。
- 重启服务会丢失内存里的任务记录，不会删除已写出的结果。服务重启不会自动断点续跑。
- 如果提示“响应丢失，任务可能已启动”，先点击任务区 **刷新 / 重试** 确认，不要反复提交。
- 手动从某张继续时，先根据报告确认排序和成功 / 失败情况，再设置 `index`。修改输入列表后，旧的索引不一定仍指向同一图片。

## 9. 保存与恢复自己的流程

**Download workflow** 保存节点、连线、画布位置、全局配置和循环模式。**Load workflow** 从本地选择 JSON 文件导入，后端会校验节点和连线。

工作流不是项目压缩包，不包含原图、权重、生成结果和任务报告。恢复前请确保服务器输入路径、模型路径仍然有效。

建议在以下操作之后下载一次：完成连线、修改提示词 / 模型参数、设置目录、开始长时间批量运行之前。

## 10. 常见问题速查

| 现象 / 提示 | 优先检查 |
| --- | --- |
| “批量运行前请在保存节点直接填写 dir 输出目录” | 展开画布中的 `save` → 填 `dir` → Enter；不是右侧底部的 Output dataset directory |
| 文件夹有两张，但只跑一张 | 日志是否为 `/api/node/save-images` 或 `/api/batch/preview`？改点顶部“运行全部”；同时检查 `index` 是否为 1 |
| 看见 `8/8`，不知道跑了几张 | 这是单张推理步数，看右侧“已处理 X / N”才是总图片进度 |
| “运行全部”是灰色 | 是否开启 ↻ 逐张、连接保存终点、填写两个 dir、完成重新检查；是否已有任务、预览或未确认的提交在进行 |
| 改目录后页面仍用旧值 | 在输入框按 Enter 或离开输入框，再点“重新检查” |
| 找不到保存节点 | 点击“整理流程”，或通过顶部节点列表定位；保存终点通常在流程右侧 |
| 出现多个保存分支 | 从顶部“保存终点”下拉框选择本次运行的节点；只执行它的必要上游 |
| 保存终点依赖多个文件夹 | 当前不支持自动配对两个文件夹；一次循环的上游只保留一个文件夹输入 |
| “文件夹不存在”或没有图片 | 填服务器目录，不是本地电脑目录；检查路径、格式和 recursive |
| 日志里 `memory_attention_rope_theta` 弃用警告 | 该警告本身不表示循环失败；看后续是否有异常及任务结果 |
| 模型找不到或首次加载很慢 | SAM3 / FLUX 使用已安装的本地模型；查看节点“说明与测试”和服务器异常，不要重复点击运行 |
| 旧上传图突然无法读取 | 临时上传目录可能在服务停止时已清理；重新上传或改用服务器固定目录 |
| 页面仍显示旧按钮文案 | 强制刷新浏览器；后端代码更新后还需重启服务 |

### 每次正式批量运行前，最后核对

- [ ] 输入目录在服务器上，文件列表正确。
- [ ] 保存目录与输入分开，具有写权限。
- [ ] `index=0`，或确实希望从中间开始。
- [ ] 选择了正确的保存终点，顶部数量符合预期。
- [ ] 提示词、分割对象和生成参数已确认。
- [ ] 已试跑并检查图片，知道试跑也会写入磁盘。
- [ ] 已下载工作流；批量结束后下载报告。
- [ ] 点击的是画布顶部 **运行全部 · 写入磁盘**。
